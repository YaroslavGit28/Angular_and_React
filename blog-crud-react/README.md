# Отчёт по практической работе № 11–12
## Разработка React-приложения для управления публикациями

### 1. Цель работы

Цель работы — создать одностраничное веб-приложение на React для просмотра и управления публикациями (постами). В проекте используются маршрутизация, работа с удалённым API, управление серверным состоянием, формы и проверка введённых данных.

### 2. Используемые технологии

- **React** — построение пользовательского интерфейса на основе компонентов.
- **Vite** — запуск локального сервера разработки и сборка проекта.
- **React Router** — переходы между страницами без полной перезагрузки сайта.
- **TanStack Query** — загрузка, кеширование и обновление данных, обработка мутаций.
- **React Hook Form** — управление состоянием формы и отправкой данных.
- **Zod** и **@hookform/resolvers** — описание схемы и проверка данных формы.
- **JSONPlaceholder** — источник начальных демонстрационных публикаций при доступности сети.
- **localStorage** — локальное сохранение публикаций в браузере для надёжного создания, редактирования и удаления.
- **CSS** — оформление интерфейса и адаптация под разные размеры экрана.

### 3. Реализованный функционал

В приложении предусмотрены следующие возможности:

1. **Список публикаций.** Получение постов из API и отображение их в виде списка.
2. **Страница публикации.** Просмотр отдельного поста по его идентификатору.
3. **Создание публикации.** Отдельная страница с формой добавления поста.
4. **Редактирование публикации.** Загрузка существующих данных и их изменение через форму.
5. **Удаление публикации.** Удаление поста из списка с обновлением интерфейса.
6. **Маршрутизация.** Для списка, просмотра, создания и редактирования предусмотрены отдельные адреса.
7. **Проверка формы.** Схема Zod проверяет обязательные поля и корректность введённых значений до отправки.
8. **Состояния загрузки и ошибок.** Интерфейс сообщает пользователю, когда данные загружаются или запрос завершился ошибкой.
9. **Кеширование запросов.** TanStack Query управляет серверными данными и позволяет обновлять их после изменений.
10. **Оптимистичное удаление.** При удалении запись может сразу исчезать из интерфейса; при ошибке предусмотрено восстановление предыдущего состояния.
11. **Общая навигация и оформление.** Добавлены ссылки между основными страницами и единый стиль интерфейса.

> **Важно:** первоначальные посты загружаются из JSONPlaceholder, если он доступен. Затем каталог сохраняется в `localStorage` браузера. Создание, редактирование и удаление выполняются локально, поэтому не зависят от внешнего API и сохраняются после перезагрузки страницы на этом устройстве.

#### Назначение основных файлов

- `src/main.jsx` — точка входа приложения; подключает React, маршрутизацию, стили и провайдер TanStack Query.
- `src/App.jsx` — описывает маршруты приложения и общую структуру страниц.
- `src/styles.css` — содержит стили интерфейса.
- `src/api/posts.js` — функции запросов к API: получение списка и отдельного поста, создание, обновление и удаление.
- `src/schemas/postSchema.js` — схема валидации полей публикации.
- `src/components/PostForm.jsx` — повторно используемая форма для создания и редактирования постов.
- `src/pages/PostsPage.jsx` — список публикаций.
- `src/pages/PostDetailPage.jsx` — подробная страница выбранной публикации.
- `src/pages/NewPostPage.jsx` — страница создания поста.
- `src/pages/EditPostPage.jsx` — страница редактирования поста.
- `package.json` — список зависимостей и команды проекта.
- `vite.config.js` — настройки Vite.

### 5. Подключение и запуск проекта в Windows

#### Шаг 1. Установить Node.js

Для запуска проекта необходим Node.js с npm. Установите актуальную LTS-версию с официального сайта Node.js, затем закройте и заново откройте терминал.

Проверить установку можно командами:

```powershell
node -v
npm -v
```

Если команды выводят номера версий, среда установлена и доступна.

#### Шаг 2. Распаковать проект

1. Скачайте архив проекта.
2. Распакуйте его в удобную папку, например на рабочий стол.
3. Откройте терминал PowerShell или встроенный терминал Visual Studio Code.
4. Перейдите в папку проекта. Например:

```powershell
cd "$HOME\Desktop\blog-crud-react"
```

Если проект распакован в другое место, укажите фактический путь. В терминале должна быть открыта папка, где лежит `package.json`.

#### Шаг 3. Установить зависимости

Выполните:

```powershell
npm install
```

Команда скачает необходимые библиотеки, указанные в `package.json`, и создаст папку `node_modules`.

**Если PowerShell сообщает, что выполнение сценариев запрещено и не запускает `npm.ps1`,** это не обязательно означает ошибку проекта. В PowerShell можно вызвать Windows-команду npm напрямую:

```powershell
npm.cmd install
```

Для выполнения команд проекта аналогично используйте `npm.cmd`.

#### Шаг 4. Запустить сайт

После установки зависимостей выполните:

```powershell
npm run dev
```

Если PowerShell снова блокирует `npm.ps1`, выполните:

```powershell
npm.cmd run dev
```

В терминале Vite выведет локальный адрес. Обычно это:

```text
http://localhost:5173/
```

Откройте показанный адрес в браузере. Пока сайт нужен для работы, оставляйте терминал запущенным. Чтобы остановить сервер, нажмите `Ctrl + C` в терминале.

#### Шаг 5. Проверить работу приложения

После запуска проверьте основные сценарии:

1. Открывается страница со списком публикаций.
2. Можно перейти к просмотру отдельного поста.
3. Форма создания отображает ошибки, если обязательные поля не заполнены.
4. Корректно заполненная форма отправляется.
5. На странице редактирования загружаются данные выбранного поста.
6. Можно отправить изменения.
7. Удаление поста обновляет список.
8. При недоступности API приложение показывает сообщение об ошибке, а не остаётся без объяснения происходящего.

### 6. Основные маршруты

| Маршрут | Назначение |
|---|---|
| `/` | Список публикаций |
| `/posts/:id` | Просмотр публикации по ID |
| `/posts/new` | Создание публикации |
| `/posts/:id/edit` | Редактирование публикации |

Маршруты обрабатываются React Router. Благодаря этому переходы между разделами происходят внутри приложения без полной перезагрузки страницы.

### 7. Как организована работа с API

Функции работы с публикациями вынесены в `src/api/posts.js`. Это отделяет логику данных от компонентов интерфейса. При первом запуске приложение пытается загрузить стартовые посты из JSONPlaceholder с тайм-аутом 7 секунд. Если внешний API недоступен, показываются демонстрационные записи. После первой загрузки данные хранятся в `localStorage`; CRUD-операции выполняются локально и не ждут ответа внешнего сервера.

Приложение использует тестовый сервис JSONPlaceholder. Взаимодействие включает:

- получение коллекции постов;
- получение одного поста по идентификатору;
- отправку запроса на создание;
- отправку запроса на обновление;
- отправку запроса на удаление.

TanStack Query используется для управления загрузкой и кешем. После создания и редактирования кеш обновляется сразу, затем приложение возвращает пользователя в каталог без ожидания повторного сетевого запроса.

### 8. Работа с формами и валидацией

Компонент `PostForm.jsx` использует React Hook Form для управления значениями формы. Правила проверки вынесены в `postSchema.js` и описаны через Zod.

Такой подход позволяет:

- централизованно описать требования к полям;
- показывать сообщения об ошибках рядом с полями;
- не отправлять форму, пока данные не прошли проверку;
- повторно использовать форму при создании и редактировании поста.

### 9. Возможные проблемы и их решение

**Проблема: `npm` не запускается, сообщение о запрете выполнения сценариев.**

Решение: в PowerShell попробуйте `npm.cmd install` и `npm.cmd run dev`.

**Проблема: команда `npm install` не находит `package.json`.**

Причина: терминал открыт не в папке проекта. Перейдите в каталог, в котором расположен `package.json`, и повторите команду.

**Проблема: сайт не открывается по адресу.**

Проверьте, что команда `npm run dev` продолжает работать, и откройте адрес, который указан в выводе Vite. При необходимости проверьте, не занят ли порт.

**Проблема: список постов долго загружается.**

Запрос к JSONPlaceholder ограничен тайм-аутом в 7 секунд. Если внешний сервис недоступен, приложение автоматически создаёт демонстрационные записи и сохраняет их локально.

**Где хранятся созданные посты?**

В `localStorage` текущего браузера. Данные сохраняются после перезапуска страницы, но доступны только в этом браузере и на этом устройстве. Очистка данных сайта в браузере удалит и эти публикации.

### 10. Результат работы

В результате создан React-проект для работы с публикациями. В нём организованы отдельные страницы списка, просмотра, создания и редактирования; вынесены API-запросы и схема валидации; подключены React Router, TanStack Query, React Hook Form и Zod. В README приведены структура проекта, описание основных компонентов, порядок установки зависимостей, запуск в Windows и способы устранения распространённых проблем.

### 11. Вывод

В ходе работы были объединены основные инструменты React-разработки: компонентный подход, маршрутизация, работа с REST API, управление серверным состоянием и валидация форм. Проект можно использовать как основу для дальнейшего развития CRUD-приложения. Локальное хранение через `localStorage` позволяет полноценно проверять CRUD-сценарии без собственного сервера. Для общего доступа к данным с разных устройств потребуется backend или API с базой данных.
